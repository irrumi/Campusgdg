# Локальный интерфейс с существующим gateway

Основной вариант репетиции использует уже размещённого облачного агента.
Gemini/GitHub ключи вводить не нужно. GCP не изменяется.

```powershell
.\.venv\Scripts\python.exe scripts/run_local.py
```

Откройте **http://127.0.0.1:8501** → **Настройки агента** → **Дополнительные параметры**.
Адрес gateway подставляется из публичного `agent.connection.json`. В поле
**«Ключ доступа»** введите прежний ключ приложения и сохраните настройки.
Это ключ авторизации вашего gateway, не Gemini API key и не GitHub token.
Поле скрыто; ключ хранится в текущей серверной сессии, не экспортируется в отчёт
и не записывается запуском в файлы. Ключ в чат не присылайте.

Если `AGENT_API_KEY` уже есть в окружении, интерфейс подставит его автоматически.
Локальные `.env`, `vertex.config.json` и файлы Google-авторизации запуск не читает.
Для другого gateway задайте `AGENT_API_URL` или `--url https://…/api/v1/chat`.
Передавать ключ аргументом командной строки не нужно.

Если порт занят или системный proxy не пропускает запросы:

```powershell
.\.venv\Scripts\python.exe scripts/run_local.py --ui-port 8502 --direct
```

`--direct` обходит proxy только для выбранного gateway и localhost в создаваемом
процессе. Проверка TLS остаётся включённой. `Ctrl+C` останавливает созданный UI.
Уже запущенные пользовательские процессы запуск не закрывает.

## Что именно работает где

- Проверка задания и репозитория отправляется через существующий gateway.
  Нужен структурированный ответ `deadline.action=analyze`, привязанный к SHA файла,
  с требованиями, доказательствами и журналом. Обычный ответ чата не принимается.
- После получения проверки расчёт, перепланирование, применение и Undo выполняются
  локально. В журнале расчёта указано `execution: local`; облачный агент не вызывается.
- Успешный локальный расчёт не меняет индикатор соединения на «ответ агента подтверждён».
- Старый облачный агент может не поддерживать проверку «До сдачи». В таком случае
  UI сохраняет данные и предлагает **«Проверить через совместимый режим»**.
  Это отдельный настоящий анализ, а не принятие старого текстового ответа за проверку.

## Совместимость со старым gateway

Кнопка использует тот же адрес и сохранённый ключ приложения. Короткая инструкция
передаётся в `message` (не более **4000 символов**, фактический лимит опубликованного
gateway). Полный текст файла с номерами страниц/абзацев, JSON-схема и доказательства
передаются через существующее поле `student_context.campuspulse_review`; старый агент
уже добавляет этот контекст к запросу модели. Поля `files` и `mode` от старого API
не требуются. Модель возвращает JSON требований, запросов чтения и выводов. Локальный
код проверяет схему, цитаты по исходному файлу, принадлежность доказательств репозиторию
и цитаты, подтверждающие выводы. Обычный текст или выдуманные цитаты не подтверждают
готовность. Модель сама выбирает чтения в пределах трёх раундов и восьми операций.

Чтения выполняет наш **Custom Public GitHub MCP**, запускаемый как stdio-процесс
(`agent/public_github_mcp.py`). Он анонимно читает публичный GitHub REST API.
Это собственный MCP-сервер, **не официальный авторизованный GitHub MCP**.
Ему не передаются ключ gateway, Gemini/GitHub ключи или credential-файлы.
Файлы и CI привязаны к одному фактически полученному коммиту. Один фрагмент
ограничен 6000 символами, общий объём доказательств — 16000; усечение помечается.
Закрытые репозитории, rate limit и недоступные данные остаются непроверенными.
Локальный предел передаваемого контекста — 200000 символов. При превышении проверка
не отправляется: задание нужно разделить. Текст задания не усекается молча.

В журнале видны отдельно `gateway_model`, `public_github_mcp.read_file` и другие
фактические чтения, а затем локальный `plan_before_deadline`. Точное имя модели
старый gateway не сообщает — оно не выдумывается. GCP не изменяется.

После чтения источников агент может один раз пересмотреть предварительную
неоднозначность. Например, требование успешного завершения CI проверяется по
зафиксированному результату провайдера, а не по придуманным дополнительным требованиям
к составу тестов. Снятие уточнения требует точных цитат; настоящие пробелы в условии
сохраняются. Отдельно допускается одна попытка исправить ссылки/цитаты итогового вывода.
Причины отклонения показаны в карточке, все фактически прочитанные данные — в
«Полученные источники». Само чтение файла не означает выполнения требования.

`docs/test_schedule.pdf` содержит учебное расписание, а не критерии реализации
проекта. Для проверки репозитория используйте `examples/deadline-demo/assignment.txt`
или настоящее условие своей работы. При замене файла после ошибки сначала нажмите
**«Закрыть ошибку»**, чтобы новый запрос использовал новый файл.

## Репетиция

Используйте [подготовленные входные данные](../examples/deadline-demo/README.md).
Календарь и оценки в пакете условные и явно помечены. Результаты Gemini/GitHub
не предзаданы; их нужно получить настоящими вызовами. Даты 22–24.10.2026
сдвиньте, если показываете сценарий позже.

Порядок: проверить готовность → открыть цитату и доказательство → ввести оценки
и срок → рассчитать → применить → показать обычный календарь → вернуться →
«Завтра только час — пересчитать» → сравнить переносы → применить повторно.
Проверьте отсутствие дублей и сохранность посторонних занятий.

Если проверяемый файл требует только README и успешный CI и оба пункта выполнены,
оставшейся работы по этому файлу нет. Для содержательной репетиции перепланирования
используйте настоящее задание с незавершёнными пунктами или подготовленную рабочую
постановку команды из пакета выше. Статусы и оценки не подгоняются под сценарий.

## Дополнительный вариант: отдельный локальный агент

Только если намеренно нужен отдельный агент со своими ключами:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-local.txt
.\.venv\Scripts\python.exe scripts/run_local.py --standalone
```

Лишь этот режим запрашивает Gemini/GitHub ключи скрытым терминальным вводом.
Он использует настоящий Gemini API и официальный GitHub MCP; не подключается
к старому Agent Engine и не подтверждает облачное развёртывание новой версии.
Он не нужен для использования существующего gateway.

`backend: vertex-agent-engine`. POST без ключа приложения вернул HTTP 401.

README. После исправления обработки предварительной неоднозначности пользователь
подтвердил также итоговый статус «Подтверждено» для CI в той же вкладке. Это
репетиция при участии пользователя, а не автоматизированная проверка его закрытой
сессии. Отдельная настоящая
проверка Custom Public GitHub MCP прочитала корень, README, gateway и CI коммита
