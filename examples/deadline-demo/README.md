# Подготовленные входные данные для демо «До сдачи»

Это пакет для репетиции, а не готовая запись успешного облачного запуска.
Факты о коде взяты из настоящего репозитория команды; расписание и оценки времени
являются явно условными входными данными участника. Ответы Gemini/MCP не подменяются.

## Файлы

| Файл | Назначение |
|---|---|
| `assignment.txt` | Загрузить в «До сдачи»: рабочая постановка команды с четырьмя проверяемыми требованиями |
| `calendar.json` | Точные даты, занятые интервалы и ограничения для репетиции; это справочный JSON, отдельного импорта календаря в UI сейчас нет |
| `calendar-prompt.txt` | Вставить в обычный чат для добавления трёх помеченных «Демо:» событий; проверить фактическое сохранение |
| `effort-estimates.json` | Пример оценок оставшейся работы, вводимых вручную после живой проверки |
| `SOURCE_CHECK.md` | Проверенные факты о опубликованном коде и ссылки на конкретный коммит |

Репозиторий для поля GitHub: **https://github.com/irrumi/Campusgdg**.
Постановка составлена из реальной задачи разработки этой команды. Это не выданное
за преподавателя задание. Для показа полноценной учебной работы можно заменить
только `assignment.txt` и ссылку на соответствующий студенческий репозиторий.

## До выхода к жюри

1. Для репетиции без изменения GCP запустить `scripts/run_local.py` по
   [инструкции локального запуска](../../docs/LOCAL_DEMO.md). Использовать прежний
   ключ приложения в настройках UI; новые Gemini/GitHub ключи не нужны.
   Проверка обращается к существующему gateway и требует совместимого ответа
   агента. Расчёт и перепланирование выполняются локально и отмечены в журнале.
   Для отдельного облачного показа нужна публикация обоих сервисов по
   `docs/DEADLINE_MODE.md`; локальная репетиция её не подтверждает.
2. Провести один настоящий анализ файла и репозитория через UI. Убедиться, что
   вернулись цитаты, доказательства и журнал, а не только доступный health endpoint.
3. Использовать отдельную сессию для репетиции. Добавить события из таблицы ниже
   через календарь либо запросом из `calendar-prompt.txt`. Существующее личное
   расписание не сбрасывать. Опциональные старые учебные примеры сюда не добавлять.
4. Проверить свежий `main`. На 22.10.2026 опубликованный коммит — `e1fc985`;
   в нём есть наблюдаемые проблемы передачи файлов и старого планировщика.
   После публикации исправлений они могут быть устранены. Не сохранять заранее
   отрицательные статусы ради сценария.

## Условия репетиции на 22–24 октября 2026

| Дата | Занятое время | Название |
|---|---|---|
| 22.10.2026 | 17:00–19:00 | Демо: семинар |
| 23.10.2026 | 18:00–20:00 | Демо: лабораторная |
| 24.10.2026 | 17:00–18:00 | Демо: консультация |

Учебное окно **17:00–21:00**, на это задание **до 3 часов в день**.
Сдача **24.10.2026 в 21:00**, часовой пояс UTC+5.
Начать репетицию 22 октября до 17:00. В другое время или день сдвинуть даты и
проверить ёмкость заново: приложение использует настоящее текущее время.

Если живой анализ оставил две соответствующие задачи открытыми, пример оценок:
3 часа на путь передачи файлов и 3 часа на календарное планирование. Это оценки
участника для сценария, а не утверждение о реально оставшейся работе команды:
локальные исправления уже сделаны. При иных результатах используйте оценки для
фактических открытых требований, не заставляйте агента воспроизводить этот пример.

## Показ за 2–3 минуты

Основной маршрут занимает около **2 минут 30 секунд**: настоящая проверка
репозитория выполнена перед выступлением; расчёт, применение и перепланирование
показываются вживую. Время нового сетевого анализа заранее не гарантируется.

Перед выходом:

- На **8502** завершить проверку полного `assignment.txt` через существующий gateway.
  Кнопка — «Проверить готовность» или «Проверить репозиторий снова». Открыть цитату,
  положительный результат README, замечание к gateway и квитанцию
  `public_github_mcp.read_file` с аргументом `path: agent/server.py`.
  Не обновлять эту авторизованную вкладку браузера.
- Для репетиции на этой машине доступен **8504**: он использует настоящий сохранённый
  экспорт проверки. Открыть адрес **в новой вкладке** для исходного состояния:
  прежняя вкладка уже содержит применённый пересчитанный план. На 8504 новый анализ
  модели не запускается; это прямо написано в баннере.
- До включения таймера подготовить календарь из таблицы выше, оценки по 3 часа,
  сдачу 24.10.2026 в 21:00, окно 17:00–21:00 и доступность 3 часа в день.
  Начать с исходного состояния без применённого плана и ограничения на завтра.
  На подготовленной новой сессии 8504 эти входные данные уже заполнены.
- Подготовить вкладку GitHub со ссылкой из доказательства. Файл задания, репозиторий
  и сохранённые ответы настоящие. Сказать, что расписание и оценки условные.
  Проверяется рабочая постановка нашей команды, а не выданное преподавателем задание.

В момент нажатия «Завтра только час — пересчитать» сделать короткую паузу,
дать жюри увидеть перемещение. Показывать один конкретный перенесённый блок,
а не читать весь журнал и каждую строку расписания.

Если осталось 20 секунд: в «До сдачи» → «План до дедлайна» →
«Ограничения по отдельным дням» задать 23.10.2026 **0 часов** →
«Сохранить ограничение» → раскрыть «Дедлайн и учебное окно» → «Рассчитать план».
Сказать: «Если завтра времени совсем нет, появляется дефицит один час.
Незапланированная работа остаётся видимой — решение о сроках и приоритетах принимает студент».
Это дополнительная сцена; для основного маршрута достаточно переноса при одном часе.

Если нужен именно новый вызов модели на сцене, запустить проверку на 8502 перед
началом вступления. Пока идёт запрос, показать исходный файл и архитектуру.
Если ответ задерживается, сказать: «Новый запрос ещё выполняется; продолжу на
настоящей проверке, полученной перед выступлением» и перейти к подготовленной
сессии 8504. Называть сохранённый результат сохранённым; состояние незавершённого
запроса не выдавать за успешный ответ.

## Короткие ответы на вопросы жюри

- **Где здесь автономность?** Модель извлекает требования, выбирает чтения,
  получает данные, сопоставляет источники и при необходимости пересматривает
  предварительное уточнение или исправляет ссылки. Студент задаёт оценки и
  подтверждает применение плана. Видны решения и действия, не скрытые рассуждения.
- **Где MCP и GCP?** Модель вызывается через существующий gateway и Agent Engine.
  В текущем совместимом режиме GitHub читает наш Custom Public GitHub MCP,
  запущенный локально; планирование и календарь тоже локальные. Это собственный
  MCP на Python SDK, не официальный авторизованный GitHub MCP.
- **Откуда три часа?** Это явная оценка участника для репетиции. Модель её не измеряла;
  расписание также демонстрационное. Факты о коде получены из настоящего GitHub.
- **Почему недостатки есть в вашем репозитории?** Отчёт привязан к опубликованному
  коммиту `e1fc985`, а новые локальные исправления ещё в него не входят.
  При новой проверке оценивается фактически доступная версия.

Числа 7 → 6 → 5 часов описывают доступную ёмкость этого календаря, а не готовые
ответы модели. Если в сессии есть другие события или сейчас уже позже начала
окна, свободного времени будет меньше. Настоящий анализ требований, статусы и
оценки могут изменить итоговый план.
